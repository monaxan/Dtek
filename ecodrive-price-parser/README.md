# EcoDrive price parser

Парсер ежедневно открывает EcoDrive через Chromium/Playwright, сканирует весь каталог зарядных станций, включая пагинацию (`page-2`, `page-3` и дальше), и обновляет Google Sheet.

## Что исправлено

Старая версия проверяла только ссылки, которые уже были в Google Sheet. Поэтому товар, которого изначально не было в таблице, никогда не мог появиться после обновления.

Новая версия сначала сканирует весь каталог:

`https://ecodrive.in.ua/eko-energiya/zaryadni-stancii/`

и автоматически проходит все страницы пагинации. Новые товары, которые реально имеют статус `В наличии`, добавляются в основную вкладку автоматически.

## Что обновляется

Основная таблица:

- A — название
- B — ссылка EcoDrive
- C — цена EcoDrive
- D — наличие
- F — ваш SKU
- G/H — существующие формулы не затираются; для новой строки формула копируется вниз, если она была в предыдущей строке
- I — последняя проверка
- J — статус парсера
- K — артикул EcoDrive
- L — изменение цены

При ошибке парсинга цена и наличие **не обнуляются**. В J записывается ошибка, старая цена остаётся в C.

Дополнительно создаётся вкладка `История цен`.

## Важное поведение для новых товаров

- существующие URL обновляются всегда;
- новые URL находятся автоматически из всего каталога;
- новый товар добавляется в таблицу только если карточка товара подтверждает `В наличии`;
- товары `Нет в наличии` и `Под заказ` автоматически как новые строки не добавляются;
- дубликаты определяются по URL без `?v=1`, других query-параметров и завершающего `/`.

## 1. Заменить Apps Script

Откройте нужную Google Таблицу:

`Расширения -> Apps Script`

Замените текущий код содержимым:

`apps-script/Code.gs`

Сохраните и один раз вручную запустите:

`setupEcoDriveBridge`

Теперь setup сам ищет вкладку, где в колонке B находятся ссылки `ecodrive.in.ua`. Если случайно открыта вкладка `История цен`, она не будет выбрана как источник.

В журнале выполнения появится `APPS_SCRIPT_TOKEN`.

Если токен нужно посмотреть повторно, запустите:

`showEcoDriveBridgeConfig`

## 2. Обязательно обновить Web App deployment

После изменения Apps Script старый deployment сам по себе не получает новую версию кода.

В Apps Script:

`Развернуть -> Управление развертываниями -> Изменить -> Новая версия -> Развернуть`

Либо создайте новое развертывание:

`Развернуть -> Новое развертывание -> Веб-приложение`

Параметры:

- Execute as / Выполнять от имени: **Me / Я**
- Who has access / У кого есть доступ: **Anyone / Все**

Используйте URL, который заканчивается на `/exec`.

## 3. GitHub Secrets

Repository -> Settings -> Secrets and variables -> Actions

Обязательные:

- `APPS_SCRIPT_WEBAPP_URL` — URL `/exec` из Apps Script
- `APPS_SCRIPT_TOKEN` — токен из `setupEcoDriveBridge`

Необязательные, только если EcoDrive блокирует IP GitHub Actions:

- `PROXY_SERVER`
- `PROXY_USERNAME`
- `PROXY_PASSWORD`

## 4. Первый тест

GitHub -> Actions -> `EcoDrive Price Parser` -> `Run workflow`.

В логах должны появиться строки вида:

```text
Catalog page 1: ...
Catalog page 2: ...
Catalog page 3: ...
Catalog discovery complete: XX unique product URLs
Will check XX products: existing=..., newFromCatalog=...
Done. Catalog unique=..., newInStockAppended=...
```

После завершения проверьте основную вкладку:

- C — актуальная цена;
- D — наличие;
- I — время проверки;
- J — `OK`;
- K — SKU EcoDrive;
- L — изменение цены;
- внизу основной вкладки должны появиться новые найденные товары `В наличии`.

`История цен` не является полным каталогом. В ней появляются строки только когда цена/наличие изменились либо когда новый товар впервые добавлен.

## Автоматический запуск

Workflow запускается раз в сутки по cron:

```yaml
37 2 * * *
```

GitHub cron использует UTC.

## Защита от ошибок

- полный обход пагинации каталога;
- минимум поддерживается `page-1`, `page-2`, `page-3`, далее до найденной последней страницы;
- максимум по safety-limit — 20 страниц;
- защита от повторяющейся последней страницы;
- 3 попытки открыть каждую карточку;
- последовательный обход без агрессивного параллелизма;
- случайная пауза между товарами;
- JSON-LD -> meta -> DOM fallback для определения цены;
- старая цена не заменяется на `0` при ошибке;
- URL сверяется перед записью;
- изменения цены и наличия пишутся в историю;
- при ошибках сохраняются debug screenshots в GitHub Actions artifact.
